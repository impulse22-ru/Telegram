## 1. Общая модель продукта

«TikTok × маркетплейс поверх Telegram». Контент (видео) публикуется в Telegram-канал,
наш сервер индексирует его и отдаёт в вертикальную ленту. Вокруг ленты — магазины,
товары, заказы, подписки, отзывы и панель модерации. Клиент — модифицированный
Telegram Android, в котором добавлена панель **Media Feed**.

Роли: **пользователь** (лента, магазины, покупки) и **администратор** (модерация).

## 2. Серверная часть

### 2.1 HTTP API

#### Авторизация (публично)

| Метод | Путь | Функционал |
|---|---|---|
| POST | `/v1/auth/telegram` | Вход по Telegram-аккаунту: принимает `tg_user_id`, `phone`, `name`. Создаёт пользователя, если нет. Возвращает пару **access** (JWT, ~15 мин) + **refresh** (opaque, 30 дн). |
| POST | `/v1/auth/refresh` | Ротация refresh-токена: старый отзывается (sha256 кладётся в Redis), выдаётся новая пара. |
| POST | `/v1/auth/logout` | Полный выход: отзыв refresh-токена. |
| GET | `/health` | Живость процесса. |
| GET | `/metrics` | Prometheus-метрики API: запросы/сек, статусы, длительность, uptime. |

#### Лента и видео (authMW)

| Метод | Путь | Функционал |
|---|---|---|
| GET | `/v1/feed` | Лента видео (пагинация `?offset=&limit=`, дефолт 10). Только видимые. |
| GET | `/v1/search` | Поиск видео по подстроке (`?q=`). |
| GET | `/v1/videos/{id}` | Получить видео (метаданные, `stream_url` — ссылка на relay). |
| GET | `/v1/videos/{id}/stats` | Счётчики: лайки, комментарии, просмотры. |
| POST | `/v1/videos/{id}/like` | Лайк (rlMW). |
| POST | `/v1/videos/{id}/unlike` | Снять лайк (rlMW). |
| GET | `/v1/videos/{id}/comments` | Список комментариев (дерево, вложенность `depth`). |
| POST | `/v1/videos/{id}/comment` | Добавить комментарий (rlMW). |
| POST | `/v1/videos/{id}/report` | Жалоба на видео (rlMW, причина обязательна). |
| POST | `/v1/videos/{id}/view` | Засчитать просмотр (идемпотентно: 1 на пользователя/видео). |
| POST | `/v1/join` | Оплатить вступление в канал по статусу канала; возвращает invite-ссылку. |

#### Магазины (authMW)

| Метод | Путь | Функционал |
|---|---|---|
| POST | `/v1/shop` | Создать магазин (title, description, payment_info, image_url). |
| GET | `/v1/shops` | Все магазины. |
| GET | `/v1/shops/search` | Поиск магазинов (`?q=`). |
| GET | `/v1/shops/me` | Мои магазины. |
| GET | `/v1/catalog` | Каталог товаров (пагинация). |
| GET | `/v1/catalog/categories` | Список категорий + счётчики товаров. |
| GET | `/v1/shop/{id}` | Магазин с товарами. |
| PUT | `/v1/shop/{id}` | Обновить магазин (только владелец). |
| DELETE | `/v1/shop/{id}` | Удалить магазин (только владелец). |
| POST | `/v1/shops/{id}/subscribe` | Подписаться на магазин. |
| DELETE | `/v1/shops/{id}/subscribe` | Отписаться. |
| GET | `/v1/me/subscriptions` | Мои подписки. |

#### Товары (authMW)

| Метод | Путь | Функционал |
|---|---|---|
| POST | `/v1/product` | Создать товар в магазине (title, description, price, currency, category, image_url). |
| GET | `/v1/product/{id}` | Получить товар (включая магазин и отзывы). |
| PUT | `/v1/product/{id}` | Обновить товар (только владелец магазина). |
| DELETE | `/v1/product/{id}` | Удалить товар (только владелец). |
| POST | `/v1/product/{id}/view` | Засчитать просмотр товара. |
| POST | `/v1/product/{id}/review` | Добавить отзыв: рейтинг `1–5`, текст (rlMW). |
| GET | `/v1/product/{id}/reviews` | Отзывы товара (средний рейтинг + список). |

#### Заказы (authMW)

| Метод | Путь | Функционал |
|---|---|---|
| POST | `/v1/order` | Создать заказ: продукт, количество, контакт. Цена берётся **с сервера**, а не из запроса. |
| GET | `/v1/order/{id}` | Детали заказа (только участник: покупатель или продавец). |
| POST | `/v1/order/{id}/pay` | Покупатель отмечает оплату (статус → `paid`). |
| POST | `/v1/order/{id}/cancel` | Отменить (только покупатель, до подтверждения). |
| POST | `/v1/order/{id}/confirm` | Продавец подтверждает (статус → `confirmed`). |
| GET | `/v1/order/{id}/chat` | Ссылка на чат по заказу (покупатель ↔ продавец). |
| GET | `/v1/orders/seller` | Заказы на мои товары. |
| GET | `/v1/orders/me` | Мои покупки. |

| Метод | Путь | Функционал |
|---|---|---|
| GET | `/v1/stats/me` | Моя статистика (просмотры, лайки, активность). |
| GET | `/v1/stats/sales` | Статистика продаж по моим магазинам (заказы, выручка). |

#### Администрирование (authMW + adminMW)

| Метод | Путь | Функционал |
|---|---|---|
| GET | `/v1/admin/stats` | Сводка: пользователи, видео, жалобы, продажи. |
| GET | `/v1/admin/top` | Топ видео по просмотрам. |
| GET | `/v1/admin/reports` | Все жалобы. |
| POST | `/v1/admin/reports/{id}/status` | Сменить статус жалобы (`new/open/resolved`). |
| POST | `/v1/admin/videos/{id}/ban` | Забанить видео (скрыть из ленты). |
| POST | `/v1/admin/videos/{id}/unban` | Разбанить. |
| DELETE | `/v1/admin/videos/{id}` | Удалить видео. |
| DELETE | `/v1/admin/comments/{id}` | Удалить комментарий (флаг `deleted`). |
| GET | `/v1/admin/comments` | Все комментарии (для модерации). |

| POST | `/v1/admin/shops/{id}/suspend` | Заморозить магазин. |

#### Загрузка файлов (authMW)

| Метод | Путь | Функционал |
|---|---|---|
| POST | `/v1/upload` | Загрузка изображения (body = байты) → сохраняет в `uploadDir`, возвращает URL `/uploads/<file>`. |
| GET | `/uploads/*` | Раздача статических файлов (`http.FileServer`). |

**Промежуточные middleware:** `requestLog` (лог+метрики), `corsMW`, `authMW`
(Bearer-JWT + проверка бана), `rlMW` (per-user rate-limit для like/comment/report/review),
`adminMW` (роль `admin`).

### 2.2 Воркер (`cmd/worker`)

Процесс, живущий с ботом (локальный Bot API, long polling):

- **Индексация канала**: слушает `channel_post` в `FEED_CHAT_ID`, по `video`-сообщению
  сохраняет видео (дедупликация по `tg_msg_id`), статус `visible`, метаданные, `file_id`.
- **Команды бота** (для оператора):
  - `/start`, `/help` — справка;
  - `/search <q>` — поиск по индексированным видео;
  - `/top <n>` — топ по просмотрам;
  - `/stat` — сводная статистика (видео, просмотры, пользователи).
- **Одобрение вступлений**: автоматически одобряет `chat_join_request` в канал.
- **Проверка безопасности**: лента отдаёт только `visible` видео.

### 2.3 Релей (`cmd/relay`)

Прокси-сервис стриминга:

| Метод | Путь | Функционал |
|---|---|---|
| GET | `/media/stream/{id}` | Стрим видео по Range: проверяет `status=visible`, качает файл с Telegram CDN (локальный Bot API → `getFile` → `downloadFile`), пишет в кэш (`.part` → атомарный rename), отдаёт через `http.ServeContent` (Range/Last-Modified). |
| GET | `/health` | Живость. |
| GET | `/metrics` | Метрики: потоки/сек, байты, cache hits, not_found. |

Кэш — на диске (`media_cache/`, ключ = `video_id`). Видео самого файла на Telegram
не дублируется: у нас только кэш для раздачи, не источник истины.

## 3. Клиентское приложение

### 3.1 Точки входа

Deep links внутри клиента (обрабатываются в `LaunchActivity`):

- `tg://feed` → **MediaFeedActivity** (лента видео);
- `tg://catalog` → **MediaCatalogActivity** (магазины/каталог/заказы);
- `tg://admin` → **MediaAdminActivity** (панель администратора).

Все три — автономные экраны поверх Telegram. Настройки сервера (API URL, relay URL)
конфигурируются через `SharedPreferences` (`media_feed_config`: `api_url`, `relay_url`,
`token`, `refresh_token`).

### 3.2 Media Feed — лента видео

- **Вертикальная TikTok-лента**: пейджер списков, страницы по N видео, автовоспроизведение
  с `ExoPlayer`, пауза при потере фокуса, recycling плееров (`release` при удалении позиции).
- **Пагинация**: дозагрузка страниц при прокрутке к концу (`hasMore`).
- **Поиск**: диалог поиска по видео, отдельный режим отображения результатов.
- **Действия с видео**:
  - лайк / снять лайк (кнопка ♥ с即时-обновлением счётчика);
  - комментарии (список + диалог добавления; дерево с вложенностью и «деleted»-визардом);
  - репост/шара (шарится ссылка из контекста);
  - жалоба на видео (диалог с причиной);
  - просмотр: счётчик засчитывается автоматически при старте ролика.
- **Счётчики**: у каждого ролика — лайки, комментарии, просмотры (статика с сервера).
- **Отрисовка**: кастомные view-холдеры (обложка, градиенты, прогресс-бар, кнопки),
  dark-тема.

### 3.3 Media Catalog — магазины и каталог

Главный экран-навигатор бизнеса:

- **Лента товаров (каталог)** + **категории-чипы** (горизонтальная лента чипов,
  фильтрация на лету, у чипов — счётчик товаров).
- **Магазины**:
  - просмотр списка и карточки магазина (владелец, описание, реквизиты оплаты);
  - создание/редактирование магазина (в т.ч. из привязанного TG-чата — «создать из чата»);
  - удаление своего магазина с подтверждением;
  - подписка/отписка на магазин;
  - поиск магазинов.
- **Товары** (создание/редактирование/удаление, только владелец):
  - название, описание, цена + валюта, категория;
  - **выбор картинки**: системный picker (`REQ_IMAGE_PICK`), компрессия до ~1280px JPEG,
    загрузка на сервер (`/v1/upload`), URL подставляется в товар.
  - карточка товара: цена, магазин, отзывы, кнопка «Купить».
- **Отзывы**: редактор рейтинга 1–5 + текст, просмотр с средним баллом.
- **Заказы**:
  - мои заказы (покупки): создать по товару (количество, контакт), оплатить, отменить;
  - заказы продавца: подтвердить;
  - ссылка на чат по каждому заказу;
  - статус отображается (new/paid/confirmed/cancelled).
- **Статистика продавца**: просмотры/заказы по моим магазинам.
- **Меню навигации**: лента ↔ каталог ↔ магазины ↔ заказы ↔ статистика ↔ подписки.

### 3.4 Media Admin — панель администратора

Только для роли `admin`:

- **Сводка**: статистика платформы (пользователи, видео, жалобы, продажи) + топ по просмотрам.
- **Жалобы**: список, просмотр, смена статуса (`new/open/resolved`).
- **Модерация видео**: бан/разбан/удаление.
- **Модерация комментариев**: список, удаление (софт-флаг `deleted`).
- **Модерация пользователей**: бан/разбан.
- **Магазины**: заморозка (suspend).
- **Фильтр-слова**: просмотр, добавление, удаление запрещённых слов.

### 3.5 API-клиент приложения и авторизация

`MediaFeedServerApi` — тонкий HTTP-клиент (`HttpURLConnection` на `api_url`):

- **Auth**: `auth()` при входе (по `tg_user_id` из аккаунта Telegram), сохранение
  `access` + `refresh` в prefs.
- **Auto-refresh**: при `401` в любом запросе (и в `uploadImage`) автоматически
  вызывает `refresh()`, обновляет токен и повторяет запрос; guard-флаг `refreshing`
  защищает от гонок параллельных запросов.
- **Покрытие**: все эндпоинты API обёрнуты в методы (feed/search/like/comment/report/
  view, shops/products/subscribe, orders/pay/cancel/confirm/chat, stats, admin, upload).
- **Стриминг**: `streamUrl(videoId)` = `relay_url + /media/stream/{id}`, экраны тянут
  видео прямо с relay.

## 4. Сквозные сценарии

**Просмотр каталога и покупка.**
Пользователь открывает `tg://catalog` → чипы категорий → товар → «Купить» → форма
заказа (кол-во, контакт) → сервер создаёт заказ по серверной цене → статус `new`.
Пользователь отмечает оплату (`paid`), продавец подтверждает (`confirmed`).

**Публикация видео.**
Оператор загружает ролик в канал → воркер индексирует → видео появляется в ленте
всех пользователей (status `visible`).

Остальные сценарии линейно выводятся из таблиц эндпоинтов в разделе [2](#2-серверная-часть).
